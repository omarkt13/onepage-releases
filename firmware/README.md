# OnePage Mini firmware

Firmware for the OnePage Mini e-ink companion (nRF54L15). It implements
`onepage-mini-firmware-spec.md` (draft 2) and the Bluetooth contract in
[`../docs/protocol.md`](../docs/protocol.md).

Platform: nRF Connect SDK **v3.0.2** (Zephyr 4.0.99), sysbuild with MCUboot.

## Build

```bash
west build -b nrf54l15dk/nrf54l15/cpuapp firmware -d build-dk
```

```bash
west build -b onepage_mini/nrf54l15/cpuapp firmware -d build-mini -- -DBOARD_ROOT=$PWD/firmware
```

The custom board needs `-DBOARD_ROOT` because sysbuild resolves the board
before it reads the application's `CMakeLists.txt`.

Flash a DK:

```bash
west flash -d build-dk
```

Firmware update over Bluetooth uses `build-*/dfu_application.zip` (MCUmgr SMP).

### Host tests (no SDK needed)

```bash
cmake -S firmware/tests/host -B build-host && cmake --build build-host && ctest --test-dir build-host
```

`test_vectors` checks every codec against `shared/test-vectors/vectors.json`
(produced by `shared/tools/opproto.py`, the reference encoder). The app
checks the same file, so the two sides cannot drift apart unnoticed.
`test_behaviour` covers phone-away timing, transfer resume, calendar atomic
swap, app-filter eviction, the notification list, gestures, navigation,
quiet hours, the data-request schedule and the clock.
`test_coverage` covers damaged calendar and book files, the calendar list
while an all-day event runs, UTF-8 edge cases, reader paging past its
history, the schedule after a disconnect, and small reply encoders.

Bench tests: [`../docs/TESTING.md`](../docs/TESTING.md). For the phone-away
erase test, `-Dfirmware_CONFIG_ONEPAGE_TEST_AWAY_ERASE_MIN=10` makes a bench
build that erases after 10 minutes in place of 7 days. Never ship it.

### Memory (last build)

| Board | App flash | App RAM | MCUboot flash |
|---|---|---|---|
| nrf54l15dk/nrf54l15/cpuapp | 391 KB of 698 KB | 217 KB of 256 KB | 46 KB of 54 KB |
| onepage_mini/nrf54l15/cpuapp | 392 KB of 698 KB | 217 KB of 256 KB | 46 KB of 54 KB |

The FLPR (RISC-V) core is not used, so its 68 KB RAM and 96 KB RRAM go to
the application core (as in Nordic's own samples). RAM use is mostly the
frame buffer (52 KB), the notification list (40 KB) and the calendar with
its staging copy (32 KB).

## Privacy rules as built

* Notification text and music details are in RAM only. They are erased 2
  minutes after the link drops, with a full refresh so no trace stays on
  the panel. iOS sends them again on reconnection.
* Calendar, settings and the app filter are in internal RRAM. Books are the
  only data on the external flash.
* Pairing is refused outside the 2-minute window. The window opens from
  Settings, Pair a new phone, or by an NFC tap when no phone is paired.
  Opening it erases calendar, weather, settings and the app filter.
* After 7 days away the calendar and weather are erased.

## Deviations from the specs

| Spec | As built | Why |
|---|---|---|
| Protocol 3: complete name in the advertising packet | Shortened name `OnePage` in the scan response, with the ANCS solicitation | Flags, 128-bit UUID and manufacturer data use 30 of 31 bytes. iOS reads the full name from the GAP Device Name after connecting |
| Firmware 8: display supply cut between refreshes | Cut after `CONFIG_ONEPAGE_EPD_POWER_HOLD_MS` (2 min) without a refresh | Partial refresh needs the previous image in the controller RAM, which is lost when the supply is cut. Holding the last image in MCU RAM would need another 52 KB |
| Firmware 8: LED blinks from a hardware timer with the CPU asleep | LED patterns are short timed sequences (under 1 s) from a kernel timer | Only alert patterns blink; there is no continuous blink. A GRTC-driven blink can be added if one is wanted |
| Firmware 7: locked Home after 2 minutes away | Locked Home, except when the Reader, Library or Settings is open | Books stay readable while away (spec 7); those screens show nothing private |
| App 4.6: erase covers calendar, weather, settings, filter, pairing | "Erase and reset" also deletes books | Protocol 5.7 (`ERAS`) includes books; pairing a new phone keeps books |
